# Androidバックアップ脅威モデル

最終更新日: 2026-07-26

## 問題

蔵書データには、タイトル・ISBNから推測できる関心や健康・思想等の情報、読書状態、自由入力の置き場所が含まれます。置き場所には部屋名や施設名など物理的位置につながる文字列も入力できます。利用者が明示操作していないクラウドへこれらを保持すると、「端末内中心」という期待と一致しません。

## 保護対象と脅威

| 対象 | 想定する機密性 | 主な脅威 |
| --- | --- | --- |
| タイトル・著者・ISBN・NDC | 関心、思想、健康状態等の推測につながる | バックアップアカウント侵害、提供者・第三者によるアクセス |
| 読書状態 | 行動履歴や嗜好の推測につながる | 長期保持、意図しない復元先への展開 |
| 置き場所 | 自由入力の部屋名・施設名等を含み得る | 物理的位置や生活環境の推測 |
| 手動バックアップファイル | 上記すべてと内部IDを含む | 共有先の誤選択、平文ファイルの漏えい |

対象外とする脅威は、ロック解除済み端末を操作できる攻撃者、root化端末、悪意あるOS・端末移行実装です。これらはアプリのサンドボックスとバックアップXMLだけでは防げません。

## 採用方針

| 経路 | 方針 | 根拠 |
| --- | --- | --- |
| OSクラウドバックアップ | 全対応APIで全ドメインを除外 | 明示同意なしのクラウド保持を避け、将来追加するファイルもfail-closedにする |
| 端末間転送 | API 28以降はRoom DBだけ許可 | 機種変更時の復元性を保ちつつ、設定・一時ファイルを転送しない |
| API 23〜27のOS転送 | クラウドと安全に分離できないため除外 | プライバシーを復元性より優先する |
| 手動完全バックアップ | 全APIで利用者が保存先を選んだ場合だけ許可 | 明示操作、検証・チェックサム・復元前退避を備える |
| JSON / CSV | 全APIで利用者が保存先を選んだ場合だけ許可 | 可搬性と編集性を提供する。完全復元用途ではない |

Manifestの `android:allowBackup="true"` は、許可した端末間転送へ参加するため維持します。これはクラウド許可を意味せず、実際の対象は次のバージョン別XMLで制限します。

- API 23〜27: `res/xml/backup_rules.xml` が全9ドメインを除外する。
- API 28〜30: `res/xml-v28/backup_rules.xml` が `deviceToDeviceTransfer` フラグ付きの場合だけ `database` を含める。
- API 31以降: `data_extraction_rules.xml` が `cloud-backup` の全9ドメインを除外し、`device-transfer` は `database` だけを含める。
- `cacheDir`、`codeCacheDir`、`noBackupFilesDir` はAndroid仕様でも常に対象外である。復元前の自動退避は `noBackupFilesDir` に置く。
- iOS等へのcross-platform transferは構成せず、対応アプリも提供しない。

## 既存利用者への影響

- 更新後に作成されるOSクラウドバックアップへ蔵書DBは含まれない。アプリの再インストールだけではクラウドから蔵書を戻せなくなる。
- 過去版がすでにアップロードしたスナップショットは、この更新だけでは直ちに削除できない。保持期間と削除方法は端末・バックアップ提供者・アカウント設定に従う。
- API 28以降の対応端末ではOSの端末間転送を利用できる。端末やメーカーによる実装差があるため、重要な移行では手動完全バックアップも作成する。
- API 23〜27ではOS移行が使えないため、手動完全バックアップを使用する。

## ロールバック

XMLのクラウド除外を外し、対象データを明示的に `include` すれば再度クラウドバックアップを許可できます。その場合はアプリ内文面、`PRIVACY.md`、README、ストア申告を同じリリースで更新し、暗号化要件と利用者同意を再評価します。除外期間中にアップロードされなかったデータは遡って復元できません。DBスキーマは変更しないため、アプリコードのロールバックにデータ移行は不要です。

## 検証

### 自動検査

```bash
./gradlew verifyBackupPolicy
```

このタスクはManifestと3つのXMLをDOM解析し、API 23〜27の全除外、API 28〜30のD2D条件、API 31以降のクラウド全除外とDB限定D2Dを検査します。通常の `check` にも組み込まれています。

### リリース前のOS別確認

1. API 27、30、31、最新APIの端末またはエミュレーターへrelease候補をインストールし、識別可能なタイトル・読書状態・置き場所を登録する。
2. 各端末で `adb shell bmgr enabled` と `adb shell dumpsys backup` を記録し、公式手順のローカルtransportで `adb shell bmgr backupnow dev.ndcshelf.app` を実行する。
3. アプリデータ消去後にクラウド相当の復元を行い、全APIで蔵書が復元されないことを確認する。
4. API 28以降の実端末2台で初期設定の端末間転送を行い、蔵書DBだけが復元され、アプリが正常起動することを確認する。API 27では蔵書が転送されないことを確認する。
5. 各APIで手動完全バックアップを作成し、別の空状態へ復元できることを確認する。
6. 結果、端末、OS、transport、メーカーをPRまたはリリースチェックへ記録する。OEM差があるため、静的検査だけでD2D互換性を保証しない。
