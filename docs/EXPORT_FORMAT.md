# 蔵書エクスポート形式

NDC Shelfは、端末内で所有する蔵書をJSONまたはCSVとしてユーザーが選んだ保存先へ書き出します。どちらもUTF-8です。「ほしい」「予約済み」の購入予定と読書セッション履歴（開始・読了・再読、評価、メモ）はJSONとCSVに含まれないため、その移行・復旧には完全バックアップ（形式v13以降）を使用してください。読書履歴をJSON/CSVへ含めない判断は明示的なもので、既存の18項目・18列の互換性を壊さず、履歴の正本を完全バックアップ1系統に保つためです。

タグはJSON v4に含まれ（タグ定義と蔵書ごとのタグ名）、インポートで往復できます。CSVは18列の互換維持のためタグを含めません（明示的な判断）。保存済み検索（検索条件コレクション）は内部タグIDへ依存するためJSON/CSVへ含めず、完全バックアップ（形式v14以降）だけで移行します。

## JSON

JSONは所有する蔵書の移行とインポートに使う形式です。購入予定を含む全データの正本は完全バックアップです。ルートには次の項目があります。

| 項目 | 型 | 説明 |
| --- | --- | --- |
| `schemaVersion` | number | 形式の互換性を判定する整数。現在は`4` |
| `exportedAt` | number | エクスポート時刻（Unix epoch milliseconds） |
| `bookCount` | number | `books`の件数 |
| `tags` | array | タグ定義（`name`と固定パレットの`colorRole`）。v4で追加 |
| `books` | array | 蔵書レコード |

各蔵書レコードは、`LibraryBook`の全項目と、v4で追加した`tags`（その蔵書の作品へ付与済みのタグ名配列、名前順）を保持します。列挙値はコード上の名前（例: `PHYSICAL`、`READING`）です。値がない任意項目は`null`で、項目自体は省略しません。

### JSONインポート

蔵書画面のインポート操作から、Storage Access FrameworkでJSONを選択します。追加のストレージ権限は要求しません。

- `schemaVersion: 1`から`4`を受け付け、未知の将来バージョンはDBを変更せず拒否します。v1にない`copyLabel`は`所蔵本`、v1/v2にない`bibliographicSource`は`NDL`、v3以前にない`tags`はタグ情報なしとして補完します。
- ルート項目、各蔵書の項目（v4は`tags`を含む19項目）、JSON型、`bookCount`との一致を検証します。v3以降は`MANUAL`由来に限り`isbn13: null`を受け付けます。
- v4のタグは、定義名の正規化・重複・色ロール・件数上限（100件）を検証し、蔵書側のタグ名は定義済みまたは既存タグ名だけを受け付けます。既存タグは名前で再利用し（色は変更しません）、スキップした既存コピーへはタグを適用しません。
- UTF-8 BOMは許容します。ファイルは10 MiB、10,000件、ネスト64段を上限とします。
- 検証後に追加・更新・スキップ件数を表示し、`copyId`競合時は既定で既存コピーをスキップします。明示的に選んだ場合だけ更新します。同じISBNで異なる`copyId`は、版情報が一致すれば既存Editionを再利用した新しいコピーとして追加します。
- 確定前はRoomを変更せず、確定後は単一トランザクションで反映します。失敗・キャンセル時は全変更をロールバックします。

入力値の正規化と安全条件は[IMPORT_SAFETY.md](IMPORT_SAFETY.md)を参照してください。

## CSV

CSVは表計算ソフトでの閲覧・分析向けです。

- 先頭にUTF-8 BOMを付けます。
- 改行はCRLF、全セルをダブルクォートで囲みます。
- 列順はJSONの蔵書項目と同じで、`copyId`から`addedAt`までの18列です。`copyLabel`と`bibliographicSource`を含みます。
- `=`、`+`、`-`、`@`から始まる値は、表計算ソフトによる数式実行を防ぐため先頭にアポストロフィを付けます。元からアポストロフィで始まる値にも1文字追加し、再import時に元値と保護マーカーを区別します。先頭に空白がある場合も、最初の非空白文字で判定します。

CSVは安全な閲覧を優先して値を保護するため、所有する蔵書の復元にはJSON、購入予定を含む全データの復元には完全バックアップを使用します。

### CSVインポート

蔵書画面のインポート操作から、Storage Access FrameworkでCSVを選択します。追加のストレージ権限は要求しません。

- UTF-8のBOM有無、CRLF / LF、ダブルクォート内のカンマ・改行・二重化した引用符を受け付けます。UTF-8以外、重複列、空の列名、不正な引用符は拒否します。
- 列順ではなく列名で対応付けます。未知列はプレビューに警告して無視し、`title`、`primaryAuthor`、`isbn13`、`classificationSource`、`mediaType`、`location`、`readingStatus`、`addedAt`の不足は拒否します。
- `copyId`、`workId`、`editionId`、`copyLabel`と、値を持たない任意項目の列は省略できます。`copyLabel`がない旧CSVは`所蔵本`として補完し、既知列の空セルは値なしとして扱います。
- エクスポート時に付けた先頭アポストロフィは、その後の最初の非空白文字が`'`、`=`、`+`、`-`、`@`の場合に1文字だけ外します。通常文字の前にある手作りCSVのアポストロフィは保持します。共通検証では前後空白も正規化します。
- IDが空または列ごとない場合、ISBNがあれば`workId`と`editionId`をISBNから決定的に生成します。ISBNがない手動書誌は取り込み単位のIDを生成し、別のISBNなし書誌と統合しません。`copyId`は取り込みごとにUUIDを生成します。
- CSVはスキーマバージョン、エクスポート時刻、`null`と空文字の区別を保持しないため、完全復元形式ではありません。完全なバックアップにはJSONを使用してください。
- ファイルは10 MiB、10,000件、表示エラー・警告は各100件を上限とします。検証後はJSONと同じ競合プレビューと単一トランザクションで反映します。

## プライバシー

エクスポートにはタイトル、著者、ISBN、読書状態、置き場所などの個人データが含まれます。アプリはStorage Access Frameworkを使用して指定されたURIへ直接保存し、NDC Shelf自身が外部サーバーへ送信することはありません。保存後のファイル管理は保存先アプリのポリシーに従います。

蔵書レコードは保存先へ逐次書き込み、ファイル全体をメモリ上に保持しません。保存開始時点の一貫した内容にするため、その時点の蔵書一覧だけをスナップショットとして保持します。

## 受け入れ条件

- JSONが全蔵書項目、スキーマバージョン、出力時刻、件数を保持する。
- CSVがUTF-8 BOM、CRLF、RFC 4180互換の引用符処理を使用する。
- CSVの外部由来文字列が表計算ソフトの数式として解釈されない。
- ユーザーが保存をキャンセルした場合はファイルを作成せず、エラーも表示しない。
- 保存成功・失敗が画面上で通知される。
- ストレージ権限やネットワーク送信を追加しない。
