# 国際化（i18n）と翻訳運用

NDC Shelf の文言リソース、ロケール方針、翻訳品質基準、CI での検証方法の正本。

対象バージョン: v0.4 系（`app/build.gradle.kts` の `versionName`）。

## ロケール方針

| ディレクトリ | 言語 | 役割 |
| --- | --- | --- |
| `app/src/main/res/values/strings.xml` | **英語** | デフォルト（fallback）。未対応ロケールの端末はここを使う |
| `app/src/main/res/values-ja/strings.xml` | **日本語** | 日本語ロケールの端末で使う |

Issue #44 以前は `values/` に日本語が入っており、日本語以外の端末でも日本語が表示される
ねじれた構成だった。Android のリソース解決では `values/` が最終 fallback になるため、
デフォルトは言語非依存に近い英語とし、日本語は `values-ja/` に置く。

移行は「既存の日本語を `values-ja/` へ `git mv` → `values/` を英訳で置き換える」順で行い、
**キー名は一切変更していない**。既存のコード・テストは `R.string.xxx` のまま動く。

`android:supportsRtl="true"` は移行前から宣言済み。レイアウトは `start` / `end` のみを使い、
`paddingLeft` / `paddingRight` / `Alignment.Absolute.*` / `TextAlign.Left|Right` は 1 箇所も
使っていない（`grep` で確認済み。CI の擬似ロケール golden で回帰を検出する）。

### 対応言語を増やすとき

1. `app/src/main/res/values-<lang>/strings.xml` を作る
2. `values/strings.xml` の全キー（`<string>` と `<plurals>`）を訳す。
   `translatable="false"` のキーは**入れない**
3. `.github/scripts/verify-translations.sh` の比較対象へ新ロケールを追加する
   （現在は英日 2 ロケール固定）
4. `ScreenshotRegressionTest` へそのロケールのケースを 1 つ以上足し、golden を記録する

### ドメイン層のメッセージ解決方法

ドメイン・データ層は `Context` を持たないため、文字列そのものではなく
`dev.ndcshelf.app.domain.text.UiMessage`（リソースID + フォーマット引数）を返す。
表示直前に UI 層で `dev.ndcshelf.app.ui.text.resolve()`（Compose）または
`UiMessage.resolve(resources)` でロケール解決する。`args` に `UiMessage` を入れると
入れ子で解決するため、「NDC 4類 自然科学」のような合成文言もリソースで組み立てられる。

これにより、端末の言語を切り替えるとインポート検証エラー・同期の受領メッセージ・
バリデーション文言まで同じロケールで表示される。

enum の表示ラベル（`ReadingStatus` / `ReadingSessionStatus` / `TagColorRole` /
`NdcCategory`）はドメインから `label: String` を外し、
`dev.ndcshelf.app.ui.text.labelRes` で表示用リソースへ写像する。

## 文字列連結と複数形

### `<plurals>`

英語は冊数で単複が変わるため、数量に名詞が直接つく文言は `<plurals>` にした（48 件）。
日本語は `other` だけを定義する（`verify-translations.sh` が `one` の混入を検出する）。

例:

```xml
<!-- values/strings.xml -->
<plurals name="scan_duplicate_owned">
    <item quantity="one">You already own %1$d copy</item>
    <item quantity="other">You already own %1$d copies</item>
</plurals>
```

```xml
<!-- values-ja/strings.xml -->
<plurals name="scan_duplicate_owned">
    <item quantity="other">すでに%1$d冊持っています</item>
</plurals>
```

Compose からは `pluralStringResource(R.plurals.x, count, count)`、
非 Composable からは `resources.getQuantityString(R.plurals.x, count, count)` で参照する。
`count` は数量の選択にだけ使われ、フォーマット引数には渡らないので、
**数量とフォーマット引数の両方**を渡す必要がある。

### 連結の解消

`"${a}と${b}"` 形式の連結は format 引数へ置換した。代表例:

| 旧 | 新 |
| --- | --- |
| `"NDC $code${category?.let { " · $it" }}"` | `library_ndc_chip` / `library_ndc_chip_with_category` |
| `"タイトル: ${a} → ${b}"` ほか5行 | `reconciliation_diff_*`（6キー） |
| `"${status.label}・${copyLabel}"` | `reading_history_entry_with_copy` |
| `"$media ・ ${owned}"` | `work_variant_edition_summary` |
| `"・$item"` | `consent_bullet_item` |
| `"${item.seriesTitle}の新しい候補"` | `series_watch_notification_title` |

日本語側の区切り記号（`・`）と英語側（`·`）はリソース内で別々に持つため、
コード側は連結を意識しない。

## 擬似ロケールでの検証

`app/build.gradle.kts` の debug ビルドで `isPseudoLocalesEnabled = true` を有効にし、
AAPT2 が擬似ロケールを生成する。release ビルドには含めないので配布サイズに影響しない。

| ロケール | 目的 |
| --- | --- |
| `en-XA` | アクセント付き・約30%伸長。**未リソース化の直書きはアクセントが付かない**ので目視で判別でき、伸長で切れも検出できる |
| `ar-XB` | RTL・双方向表示。`start`/`end` 指定の崩れとミラーリング漏れを検出する |

`ScreenshotRegressionTest` に以下の golden を追加した（合計 19 枚）。

| golden | ロケール |
| --- | --- |
| `library_light` / `library_dark` / `library_large_font` / `library_font_scale_200` / `library_medium_rail` / `library_expanded_two_pane` | `ja-rJP` |
| `insights_light` / `insights_dark` / `insights_font_scale_200` | `ja-rJP` |
| `onboarding_light` / `onboarding_dark` / `onboarding_font_scale_200` | `ja-rJP` |
| `library_en` / `insights_en` / `onboarding_en` | `en-rUS` |
| `library_pseudo_en_xa` / `onboarding_pseudo_en_xa` | `en-rXA` |
| `library_pseudo_ar_xb` / `onboarding_pseudo_ar_xb` | `ar-rXB`（`ldrtl`） |

README・配布ページ掲載用の `ScreenGalleryTest`（`scan_*` / `series_*`）と
デモGIFの `DemoRecordingTest` も `ja-rJP` に固定している。掲載物は日本語で統一し、
言語軸の回帰は `ScreenshotRegressionTest` が担当する。

golden の更新は `./gradlew recordRoborazziDebug` の結果をレビューしてコミットする。

### Robolectric テストのロケール固定

既存テストは `context.getString(R.string.xxx)` で期待値を作っており、既定ロケールが
何であっても壊れない。**ロケール非依存の期待値**が原則で、`@Config(qualifiers = "ja")` の
ような固定は使っていない。

例外は `ScreenshotRegressionTest` だけで、golden がロケールごとに異なるため
`@Config(qualifiers = ...)` にロケールを明示している（クラス既定は `ja-rJP`）。

ドメイン層のメッセージを検証するテストは、文言の部分一致ではなく
`UiMessage` の `resId` / 引数で比較する（例:
`it.reason == UiMessage(R.string.import_error_file_too_large, 8L)`）。
これも翻訳を変えても壊れない。

instrumentation テスト（`app/src/androidTest/`）は既定ロケールが `en-US` の
エミュレーターで動くため、UI 文言の直書き期待値 106 箇所を
`context.getString(R.string.x)` / `resources.getQuantityString(R.plurals.x, n, n)` へ
置き換えた。fixture のデータ（本のタイトル、置き場所名、端末名など）は
リソースではないため直書きのまま残している。

## CI での欠落・不要検出

`.github/scripts/verify-translations.sh` を `android.yml` の verify ジョブへ追加した。
検出内容:

1. `values/` にあって `values-ja/` にないキー（未翻訳）
2. `values-ja/` にあって `values/` にないキー（不要翻訳）
3. `translatable="false"` のキーが `values-ja/` に存在する
4. フォーマット引数（`%1$s` など）の集合が両言語で不一致
5. 英語 `<plurals>` に `one` / `other` が揃っていない
6. 日本語 `<plurals>` に `other` がない、または `other` 以外がある

`<string>` と `<plurals>` の両方を対象にする。Android Lint の `MissingTranslation` /
`ExtraTranslation` も `lintStandardDebug` で有効なまま（本Issue時点で警告 0 件）。

```console
$ .github/scripts/verify-translations.sh
verify-translations: OK (984 translatable keys, 2 untranslatable)
```

## 翻訳の品質基準

- **プライバシー・同意・セキュリティの文面は逐語的に等価にする。** 送信範囲、撤回の効果、
  保存期間、第三者提供の有無を過不足なく訳す。意味が広がる・狭まる訳は同意の有効性を
  損なうため不可（例: 「送信しません」を "we don't store" に置き換えない）
- 機械的な直訳を避け、UI として自然な英語にする。ただし原文にない条件・保証を足さない
- ボタン・見出しは文末の句点を付けない。説明文は付ける（日本語・英語とも）
- 同一画面内で同じ文言にならないようにする（Compose のテキスト検索テストが多重一致で
  壊れるため。例: `ai_librarian_preview_button` と `ai_librarian_preview_title`）
- 数量を伴う名詞は必ず `<plurals>` にする
