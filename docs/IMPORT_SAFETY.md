# 蔵書インポートの安全設計

JSONとCSVのインポートは、形式ごとのパーサーが生成した未検証レコードを共通基盤へ渡します。入力ファイルは信頼せず、検証とプレビューが完了するまでRoomを変更しません。

## 上限

| 対象 | 上限 |
| --- | ---: |
| 入力ファイル | 10 MiB |
| 蔵書レコード | 10,000件 |
| ID | 128文字 |
| タイトル・著者・出版社など | 2,000文字 |
| 置き場所 | 500文字 |
| URL | 4,096文字 |
| 表示する検証エラー | 100件 |

形式パーサーは実際に読み込んだバイト数を`sourceSizeBytes`として渡し、上限を超えた時点で読み込みを中止します。件数と文字列長は共通基盤でも再検証します。

## 正規化と検証

- IDと文字列の前後空白を除去し、空の任意文字列は`null`に統一します。
- ISBN-10 / ISBN-13を検証してISBN-13へ統一します。
- 列挙値は大文字小文字を無視して既知値へ変換し、未知値は既定値へ黙って置換せず拒否します。
- NDC、出版年、追加時刻、必須項目、NUL文字を検証します。
- 画像表示による任意ホストへの通信を防ぐため、`coverUrl`は現行スキーマが生成するNDL SearchのHTTPS URLだけを許可します。
- `copyId`とISBNの入力内重複、同じWork / Edition IDが異なる内容を指す参照不整合を拒否します。
- エラーはレコード番号、項目名、理由を保持します。

## 競合とプレビュー

既存蔵書との競合は`copyId`またはISBNで判定します。既定の`SKIP_EXISTING`は既存データを変更しません。ユーザーが明示的に`UPDATE_EXISTING`を選んだ場合だけ、既存のWork / Edition / Copy IDを維持して内容を更新します。

プレビューは追加、更新、スキップ件数と、検証時点の既存蔵書スナップショットを保持します。確定直前にRoom内の状態を再照合し、変化していた場合は`StalePreview`として再プレビューを要求します。

## 原子性と復旧

Work、Edition、Copyは外部キー順に、Roomの単一`withTransaction`内でupsertします。途中例外とコルーチンのキャンセルは捕捉して継続せず、Roomへ伝播させて全変更をロールバックします。DBスキーマは変更しないためMigrationは不要です。機能のロールバックはインポート基盤のコミットをrevertしますが、ユーザーが確定済みの蔵書データを自動削除してはなりません。

JSONとCSVはStorage Access Frameworkによる選択、サイズ制限付き読み込み、位置付きエラー表示、最終確認UIまで共通基盤へ接続済みです。CSVの未知列は警告して無視しますが、必須列不足、重複列、不正な引用符はDBを変更せず拒否します。
