# ADR 0007: AI司書をオプトイン・送信範囲限定で提供し、実プロバイダは接続しない

- Status: Accepted
- Date: 2026-08-01
- Issue: #42
- Decision owners: repository maintainer

## Context

蔵書を横断した選書・整理の相談は、ロードマップv1.0「Personal Librarian」の中心機能である。一方で蔵書、置き場所、読書状態、読書メモは、関心・信条・生活環境・健康状態を推測できる機密dataであり、安易なAI統合は全蔵書を第三者へ送信し得る。書誌タイトルや著者名は外部由来かつ利用者編集可能な信頼できない入力で、「以前の指示を無視して…」のような命令文を含み得る（プロンプトインジェクション）。さらに外部modelは誤答、従量課金、提供停止、ポリシー変更の影響を受ける。

本リポジトリの既存方針として、外部通信は目的別opt-in（`ConsentPurpose`）、既定OFF、送信payloadの事前提示、いつでも撤回可能を満たす必要がある（ADR 0005、`docs/PRIVACY_REVIEW.md`）。加えて、課金が発生する構成を利用者の事前承認なしに導入しない運用方針がある。

本アプリはGitHub ReleasesでAPKを配布する無料のOSSであり、利用料を回収する導線を持たない。したがって従量課金のクラウドLLMを開発者負担で常時提供する前提は成り立たず、実プロバイダを接続する場合は「誰がその費用を負担するのか」を先に決める必要がある。この決定を保留したまま接続実装だけを先行させると、課金主体・上限・停止条件が未定のまま同意画面を作ることになる。

## Decision Drivers

- 質問ごとに「どの本の、どの項目が、どこへ行くのか」を送信前に確定・提示できること
- 置き場所・読書状態・自由入力（メモ・タグ名）を既定で送信しないこと
- 信頼できない書誌文字列を、指示文ではなくデータとして構造的に隔離すること
- 回答が保存データを自動変更しないこと、根拠（参照した本）と不確実性を必ず示すこと
- 費用・rate limit・timeout・キャンセル・プロバイダ停止を、接続前から仕組みとして持つこと
- AI司書を無効にしても本棚の全機能が損なわれないこと
- 利用者承認のない従量課金を発生させないこと

## Considered Options

### Option A: 外部LLM APIへ直接接続する実装を本PRに含める

**メリット**: 実際の自然文回答が得られ、機能価値を即座に検証できる。

**デメリット**: 従量課金が承認なしに発生する。APIキーの配布・保管という新しい秘密情報管理が必要になる。プロバイダ規約・保存期間・第三者提供の開示を確定できないまま同意画面を作ることになり、「同意時点の説明」が実態と乖離する。漏えい時の影響範囲が最大になる。

### Option B: 送信範囲・プレビュー・注入対策・上限制御の仕組みを完全実装し、プロバイダは端末内の決定的実装だけを提供する

**メリット**: プライバシーと安全性の設計・実装・テストを先に確定できる。課金と情報漏えいのリスクがゼロのまま、UI・同意・上限・失敗分類・履歴削除を実運用と同じ経路で検証できる。実プロバイダ接続は`AiLibrarianProvider`の実装追加だけで済み、その時点で料金と送信内容を明示して同意versionを上げられる。

**デメリット**: 回答の質は規則ベースに留まり、自然文の相談体験は得られない。UIには未接続である旨の明示が必要になる。

### Option C: 端末内小型LLM（on-device model）を同梱する

**メリット**: 外部送信ゼロのまま自然文回答が得られる。

**デメリット**: APKサイズ・実行時memory・minSdk 23の下限端末で成立しない。新規依存とライセンス・SBOM影響が大きい。回答が非決定的になり、golden testと再現可能な検証が難しい。

## Decision

**Option B**を採用する。

### ユースケース

- この棚（現在の検索結果）から次に読む本を選ぶ
- 未読の中からテーマ別に整理案を出す
- 選んだ本・タグの範囲を概観する

### Non-goals

- 蔵書データの自動変更（読書状態・タグ・置き場所の書き換え、削除、並べ替え）
- 全蔵書を無選択で送信すること
- 実プロバイダ（クラウドLLM）への接続。本PRの対象外とし、料金と送信内容を明示したうえで将来の版で追加する
- 回答内容の正確性・網羅性の保証、外部検索や書誌の新規取得

### 規範

1. **同意**: `ConsentPurpose.AI_LIBRARIAN`（既定OFF）へ同意しない限り、`AiLibrarianProvider`を一度も呼ばない。撤回は即時に反映し、確認待ちの下書きと表示中の回答を破棄する。
2. **質問ごとのプレビュー**: `AiLibrarianRequestBuilder`が組み立てた下書きを、対象本の件数と冊名一覧・送信先・送信項目・除外項目とともに提示し、明示確認した場合だけ送信する。確認していない下書きは`confirmAsk`が送信しない。
3. **既定除外**: `AiLibrarianField`のうち`LOCATION`・`READING_STATUS`・`NOTE`・`TAGS`は`includedByDefault = false`とし、質問ごとの明示チェックでのみ含める。未選択の項目はpayload上でnull／空のまま現れない。
4. **データ隔離**: `AiLibrarianRequest.systemInstruction`は固定定数`AI_LIBRARIAN_SYSTEM_INSTRUCTION`だけを取り、`init`で他の値を拒否する。書誌は`items: List<AiLibrarianItem>`の構造化fieldへ入れ、指示文へ連結しない。値は制御文字を空白へ置換し長さ上限で切り詰める。端末内識別子（copyId・workId・ISBN）は送信せず、回答との対応は`ref`と端末内の`AiLibrarianBookReference`だけで行う。
5. **回答**: プロバイダは自然文ではなく`intent`・`reason`コードと`ref`を返す。UIは参照した本の冊名一覧と「この提案は推測です。蔵書データは変更されません。」を必ず併記する。ViewModelはリポジトリへ書き込まない。
6. **上限と失敗**: 1回あたり最大30冊（費用上限）、1日あたり最大20回、質問文200文字、timeout 15秒。キャンセル可能。プロバイダ例外は`AiLibrarianProviderErrorKind`（UNAVAILABLE / RATE_LIMITED / INVALID_RESPONSE / TRANSPORT）へ分類し、UIは上限到達を含めて明確な日本語で提示する。
7. **履歴**: 質問履歴は端末内のアプリ専用SharedPreferencesへ最大20件だけ保持し、Room・完全backup・export・OSクラウドbackupの対象にしない。「質問履歴をすべて削除」で即時に全消去できる。
8. **無効時の維持**: AI司書は独立routeの独立ViewModelで、本棚・検索・スキャン・分析はAI無効でも一切制限されない。

実プロバイダを接続する版は、(a) 費用負担者の決定（無料OSSである以上、開発者負担の従量課金を既定にはせず、利用者自身が用意した資格情報を使う方式を第一候補とする）と料金・上限の明示、(b) 送信先・保存期間・第三者提供の確定と`ConsentPurpose.AI_LIBRARIAN.policyVersion`の引き上げ、(c) 本ADRの規範1〜8の維持、を接続の前提条件とする。

## Consequences

**Positive**:

- 送信範囲の選択・プレビュー・注入対策・上限制御を、課金と外部送信ゼロのまま実運用経路で検証できる。
- 回答が決定的なため、goldenと単体テストで挙動を固定できる。
- プロバイダ差し替えは`AiLibrarianProvider`の実装追加だけで、UI・同意・上限の再設計を伴わない。

**Negative / trade-offs**:

- 現時点の回答は規則ベースで、自然文の相談体験には及ばない。利用者へは「クラウドのAIプロバイダは未接続」と明示する必要がある。
- `AiLibrarianField`の既定除外により、置き場所を前提とした整理提案は明示選択しない限り得られない。

**Residual risks**:

- 質問履歴は冊名を含むため、端末が侵害された場合は他の端末内dataと同様に読み取られ得る。
- 将来の実プロバイダ接続時は、payload最小化を守っても、通信先にIPアドレス・時刻・利用頻度などのmetadataが伝わる。
- 規則ベースの提案も誤りうる。UIの不確実性表示だけが利用者側の防御になる。

## Rollback

AI司書routeとentry pointを削除しても、Room schemaと本棚機能へ影響はない（Room変更を伴わない設計）。同意記録は`ConsentPurpose.AI_LIBRARIAN`として残るが、目的が未提供へ戻れば`ConsentScreen`の一覧から外し、以後の送信は行わない。質問履歴のSharedPreferencesは「質問履歴をすべて削除」またはアプリdataの消去で削除できる。
