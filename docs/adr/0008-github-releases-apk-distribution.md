# ADR 0008: 無料OSSとしてGitHub Releasesで署名付きAPKを配布する

- Status: Accepted
- Date: 2026-08-01
- Issue: #50、#55、#19、#29、#35
- Decision owners: repository owner

## Context

これまでリリース設計はGoogle Play Consoleでの署名付きAAB配布を前提としていた。
その前提は、Play Developerアカウントの開設（有料・所有者の判断が必要）、Play App
Signingへの登録、Data safety申告、段階ロールアウトの運用を必須にする。

一方、本アプリは端末内で完結するプライバシーファーストの個人ツールであり、
アカウント登録も課金も存在しない。所有者はこれを無料のオープンソースとして
公開する方針を選択した。ストア配布を維持すると、有料アカウントというブロッカーが
v1.0の完成判定に残り続け、ストア審査・申告の運用コストも継続的に発生する。

## Decision Drivers

- 有料サービスへの依存を持ち込まない
- 利用者が配布物の出所と完全性を自分で検証できる
- 既存利用者が上書き更新でデータを失わない
- ソースと配布物の対応関係を公開し、第三者が再現・監査できる
- 運用コストを個人開発で維持できる範囲に収める

## Considered Options

### Option A: Google Playで配布する

**メリット**: 自動更新、到達性、ストアによる完全性保証。

**デメリット**: 有料アカウントが必須。Data safety申告と審査の継続運用が必要。
配布物がストアの再署名を経るため、ソースとの対応を利用者が直接検証しにくい。

### Option B: GitHub Releasesで署名付きAPKを配布する

**メリット**: 無料。配布物・SBOM・ライセンス・署名証明書・チェックサムを同じ
Releaseへまとめられる。CIから直接生成でき、ソースとの対応が明瞭。

**デメリット**: 自動更新がない。利用者はサイドロードの許可が必要。署名鍵の
再発行手段がなく、鍵の紛失は既存利用者の上書き更新を永久に壊す。

### Option C: F-Droidへ収録する

**メリット**: 無料。F-Droidクライアントによる更新通知。

**デメリット**: ビルド再現性の要件が厳しく、Google Play Services（ML Kit）への
依存が収録可否に影響する。本アプリはバーコード認識にML Kitを使っている。

## Decision

**Option B**を採用する。GitHub Releasesで署名付きAPKを配布し、アプリストアへは
公開しない。

- `release.yml`は`assembleRelease`で署名付きAPKを生成し、`apksigner`で署名を検証して
  APK・`SHA256SUMS.txt`・署名証明書のSHA-256・mapping・SBOM・NOTICESをReleaseへ添付する。
- 署名鍵はアプリ本体の署名鍵である。Play App Signingのような再発行手段がないため、
  鍵の保全を最優先の運用事項とし、漏えい時の手順（新鍵での再配布と、利用者への
  再インストール告知）を`docs/RELEASE_PROCESS.md`へ定める。
- 段階ロールアウトの代わりに、GitHub Releasesの**pre-release → stable**の2段階を用いる。
- AABは予備成果物として生成・添付を続け、将来ストア配布へ切り替える判断を妨げない。
- F-Droid収録はML Kit依存の整理が必要なため、本ADRの対象外とする。

## Consequences

**Positive**:

- 有料アカウントに依存せず、v1.0の完成判定から課金ブロッカーが消える。
- 利用者はチェックサムと署名証明書で、配布物の完全性と配布元の同一性を検証できる。
- SBOM・ライセンス・mappingが配布物と同じ場所に並び、監査しやすい。

**Negative / trade-offs**:

- 自動更新がない。更新はGitHub Releasesの告知に依存する。
- 利用者は「不明なアプリのインストール」を許可する必要がある。
- ストアの到達性・発見性が得られない。

**Residual risks**:

- 署名鍵を失うと、既存利用者は上書き更新できなくなる（アンインストールが必要になり、
  端末内データを失う）。オフライン控えの保持が唯一の緩和策である。
- 配布済みAPKは回収できない。重大な不具合への対処は告知とroll-forwardに限られる。
- 第三者が改変APKを再配布する可能性がある。証明書SHA-256の固定掲載で緩和する。

## Rollback

ストア配布へ切り替える場合は、AABが既に生成されているため`release.yml`の添付先を
変更するだけで移行できる。ただし、Play App Signingへ登録する際は既存の署名鍵を
アップロード鍵として引き継ぎ、既存利用者が更新できる経路を維持する必要がある。
切り替えの判断と、Data safety申告の再作成は本ADRを更新して記録する。
