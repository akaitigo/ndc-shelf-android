# ADR 0004: NDL Searchを使ったシリーズ新刊候補の定期確認

- Status: Accepted
- Date: 2026-07-27
- Issue: #34

## 問題

シリーズの続刊を手作業で探さずに済むようにしたい。一方、シリーズ名は読書傾向を推測できる情報であり、外部送信を既定で有効にしてはならない。外部書誌は網羅性・正確性・提供継続性を保証しないため、「発売情報」ではなく「書誌候補」として扱う。

## データソース比較

| 候補 | 検索・網羅性 | API・認証 | 利用条件・運用 | 判断 |
| --- | --- | --- | --- | --- |
| NDL Search | タイトル・出版年検索。国内刊行物に強いが発売前情報は保証されない | SRU、APIキー不要 | 大量アクセスを避け、出典を表示。`dpid="open"`でオープンなメタデータへ限定 | 採用 |
| openBD | ISBN単位。近刊情報を含む場合がある | APIキー不要 | タイトル検索用途ではなく、販促目的や削除・更新への追従条件がある | 不採用 |
| Google Books API | `intitle`検索、海外書籍も広い | 公開データ要求にもAPI keyが必要 | キー配布・漏えい・クォータ運用が必要 | 不採用 |

一次資料: [NDL API仕様](https://ndlsearch.ndl.go.jp/help/api/specifications)、[NDL API利用条件](https://ndlsearch.ndl.go.jp/help/api)、[NDLメタデータ提供機関](https://ndlsearch.ndl.go.jp/help/api/provider)、[openBD利用規約](https://openbd.jp/terms/)、[Google Books API](https://developers.google.com/books/docs/v1/using)。

## 決定

シリーズ単位の明示的オプトインとし、既定値はOFFにする。有効化時は通知権限を先に確認し、拒否時は監視を保存しない。NDL Search SRUへシリーズ名と検索開始年だけをHTTPSで送り、`dpid="open"`、`maximumRecords=20`で取得する。蔵書、購入状態、読書状態、置き場所は送らない。

WorkManagerの一意なPeriodicWorkを7日間隔・1日flexで登録する。ネットワーク接続とbattery-not-lowを制約にし、一時障害は1時間からの指数バックオフにする。永続キューに加え、アプリ起動時にDB設定から一意ジョブを再調整する。

初回成功結果は基準線として保存するが通知しない。以降の初見だけを通知し、IDはシリーズIDとNDLレコードID（欠落時は書誌のSHA-256）から決定的に生成する。通知成功後だけ`notifiedAt`を保存する。端末時計が戻っても時刻を減少させない。権限が後から拒否された場合、候補は保存するが通知済みにはしない。

NDL障害時も保存済み候補を表示する。HTTP redirect、2 MiB超の応答、不正XML、タイトル不一致はfail-closedで除外し、候補はシリーズごとに最大200件へ制限する。

## リスク

- 網羅性不足や表記揺れによる見逃しがある。完全性を主張せず、ローカル機能を外部障害から分離する。
- 部分一致の誤検出があり得る。SRU検索後にも正規化タイトルを照合する。
- シリーズ名と通常の通信情報がNDLへ伝わる。UIとプライバシー文書へ送信項目・頻度を表示する。
- バックアップには監視設定と候補が含まれる。復元後は起動時reconcileで一意ジョブを復旧する。

## 受け入れ条件

- [x] データソースの網羅性、API、利用条件、フォールバックを比較
- [x] シリーズ単位の明示的オプトインで既定OFF
- [x] 送信識別子、頻度、候補の限界をUIとプライバシー文書に表示
- [x] 通信・バッテリー制約、指数バックオフ、一意PeriodicWork
- [x] 欲しい・予約済み・所有済みをISBNで関連付け
- [x] 外部障害、時計変更、通知拒否、重複通知をJVMテストで検証
- [x] WorkManager永続化と起動時reconcileで再起動・復元後に復旧

## ロールバック

一意Workをキャンセルして監視導線を無効化する。DB v11のテーブルは残しても既存機能へ影響しない。NDL仕様変更時は取得を停止し、保存済み候補だけを表示する。
