# 自然言語検索（端末内ルール変換）

蔵書検索欄に日本語の言い回しを入力すると、端末内のルールだけで既存の検索条件へ変換する。
解釈結果は検索欄の下にチップとして提示し、誤解釈は個別に解除できる。

- 変換は純粋関数 `dev.ndcshelf.app.domain.search.NaturalLanguageQueryParser` に閉じる。
- ネットワーク通信・新規依存・端末外への送信は一切ない。辞書も外部モデルも使わない。
- 解釈できない入力は条件を変更せず、従来どおりの部分一致検索へフォールバックする。

## 対応する検索意図

| 意図 | 例 | 変換先（`LibrarySearchCriteria`） |
| --- | --- | --- |
| 読書状態 | 未読 / 積読 / 読みかけ / 読んでいる / 読書中 / 読了した / 読み終わった / 中断中 | `readingStatus` |
| NDC類（分野名） | 総記・哲学・歴史・社会科学・自然科学・技術・産業・芸術・言語・文学 | `ndcTopClass`（先頭1桁） |
| NDC類（数字） | `4類` / `７類`（全角可） | `ndcTopClass` |
| 場所 | 書斎にある / リビングに置いてある / 書庫にしまってある | `locationQuery`（自由入力location・部屋/本棚/段名への部分一致） |
| 追加時期 | 今日追加 / 今月追加した / 先月 / 今年 / 去年買った / 昨年購入した | `addedAfterMillis`（含む）・`addedBeforeMillis`（含まない） |
| タグ | `#研究用` / `研究用タグ` | `tagIds`（既存タグの完全一致のみ） |
| 複合 | 未読の自然科学 / 書斎にある未読の本 / 去年買った未読の文学 | 上記の AND 結合 |

解釈に使われなかった語は通常の部分一致検索語（`query`）として残る。
例: `書斎にあるノルウェイの森` → 場所=書斎 + 検索語「ノルウェイの森」。

残余語からは区切りの助詞（の・が・を・は・で・と・に・へ・や・か）と、
検索の絞り込みに寄与しない一般語（本・書籍・蔵書・冊・やつ・もの）を取り除く。

## 非対応の例

主観・感想・推薦にあたる条件は解釈しない。これらは「解釈不能 → 通常検索へフォールバック」として
fixtureに明示している。

- `面白い本`
- `泣ける話`
- `おすすめの本`
- `#存在しない`（未登録のタグ名。タグとして解釈せず、そのまま検索語になる）

将来ここを広げる場合も、曖昧語をルールで推測して条件化するのではなく、
解釈チップで可視化して利用者が解除できることを前提にする。

## 優先規則

複数の解釈が同じ文字範囲に競合しうるため、次の順に確定し、確定した範囲は後続のルールから除外する。

1. **明示タグ指定**（`#名前` / `名前タグ`）
2. **追加時期**（今日・今月・先月・今年・去年・昨年 + 買った/購入した/追加した/登録した）
3. **場所**（`◯◯にある` / `◯◯に置いてある` / `◯◯にしまってある` / `◯◯に置いた`）
4. **読書状態**
5. **NDC類**（分野名・`N類`）

同一ルール内で候補が複数ある場合は、出現位置が早いもの → 一致長が長いものを選ぶ
（例: `読了した` は `読了` より優先、`社会科学` は `自然科学` と取り違えない）。

### タグ名がキーワードと衝突する場合

タグ名は利用者が自由に付けられるため、組み込みキーワードと同名のタグ（例: 「未読」というタグ）が
存在しうる。この衝突は次のように解決する。

| 入力 | 解釈 | 理由 |
| --- | --- | --- |
| `未読` | 読書状態=未読 | 裸のキーワードは常に組み込みの意味。タグの有無で挙動が変わらない |
| `#未読` | タグ「未読」 | `#` は明示的なタグ指定構文 |
| `未読タグ` | タグ「未読」 | `〜タグ` は明示的なタグ指定構文 |

名前が包含関係にあるタグ（`研究` と `研究用`）は、長い名前から先に照合する。
タグ絞り込みの上限は既存の `TagNameRules.MAX_TAG_FILTERS` に従う。

### プロンプトインジェクション耐性

解釈はルールベースの文字列一致だけで行い、書誌・タグの文字列を命令として実行する経路が構造的に存在しない。

- タグ名は正規表現へ埋め込まず、リテラルの `indexOf` 比較でのみ照合する
  （`#検証(重要)` のような記号入りタグ名も安全に扱える）。
- タイトル・著者・場所などの蔵書データは解釈の入力に一切使わない。
- 解釈結果は `LibrarySearchCriteria` の型付きフィールドにしかならず、SQLへはRoomのバインド引数として渡す。
- チップのラベルはComposeの `Text` でプレーンテキストとして描画する。

## 解釈チップの操作

- 検索欄の下に `[未読] [NDC 4類 自然科学] [場所: 書斎]` のように出現順で表示する。
- 各チップの `×` で個別に解除でき、解除した語は通常の部分一致検索語へ戻る。
  - 例: `未読の自然科学` で「未読」チップを解除 → NDC=4類 + 検索語「未読」。
- 検索文字列を変更すると解除状態はリセットされ、再度すべての解釈が提示される。
- 入力を空にすると解釈由来の条件はすべて解除される。
- 曖昧な入力（`歴史` のようにNDC分野名とタイトル語の両方になりうる語）も、解釈をチップで可視化した上で
  解除できるため、誤解釈が結果に固定されない。

## 性能とアクセシビリティ

- 解釈は既存の検索debounce（`SEARCH_DEBOUNCE_MILLIS` = 250ms）の後段で1回だけ実行する。
  打鍵ごとの解釈・再検索は行わない（`MainViewModelNaturalLanguageSearchTest` で検証）。
- 追加した検索条件はいずれもRoomのWHERE句に落ち、既存の索引利用とクエリ形状を変えない。
  NDC類は `substr(ndcCode, 1, 1)` の等値比較、場所はLIKE部分一致、追加時期は `addedAt` の範囲比較。
- チップは色ではなくテキストラベルで意味を伝え、解除アイコンには
  「解釈「◯◯」を解除」という `contentDescription` を付ける。
- 空結果時は「解釈チップを×で解除するか、別の言い回しを試してください」と次の操作を案内する。

## 永続化しない条件

`ndcTopClass` / `locationQuery` / `addedAfterMillis` / `addedBeforeMillis` は自然言語解釈から
毎回導出する一時的な条件であり、検索設定（`SharedPreferencesLibrarySearchSettingsStore`）と
保存済み検索（`SavedSearch`）には保存しない。保存されるのは入力文字列そのものなので、
復元時に同じ解釈が再現される。

## 外部モデルモードの将来設計（未提供）

クラウド解釈は本Issueでは実装しない。`ConsentPurpose.NATURAL_LANGUAGE_SEARCH` は
「クラウド解釈は未提供。提供時は検索文のみ送信し、蔵書は送らない」旨で同意画面に整合させてある。

提供する場合の前提（#42 のオプトインAI司書と共通基盤にする）:

1. **既定は端末内モード。** クラウド解釈は明示同意した場合だけ有効になる別モードとし、
   同意がない状態では一切通信しない。同意画面には送信先・送信項目・保存期間・第三者提供を提示する。
2. **送信するのは検索文だけ。** 蔵書データ（タイトル・著者・ISBN・置き場所・読書状態・タグ・件数）は
   送信しない。解釈結果は本ドキュメントと同じ型付き条件へマッピングし、
   受信した文字列をそのままSQLやコマンドとして扱わない（未知のフィールドは破棄する）。
3. **結果は必ずチップで提示する。** クラウド由来の解釈も端末内と同じチップUIで可視化し、
   個別解除できる。解釈の出所（端末内／クラウド）を表示する。
4. **失敗時は端末内モードへフォールバック。** オフライン・タイムアウト・拒否時は
   ルール変換の結果だけで検索を継続し、エラーで検索を止めない。
5. **撤回で即時停止。** 同意撤回後は通信を行わず、端末内モードへ戻る。
