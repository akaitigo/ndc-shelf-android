# データベース完全バックアップ仕様

## 目的

Roomで管理する永続的な蔵書データと、最大20件だけ保持するスキャンセッション履歴を、WALの状態に依存せず一貫した状態で退避・復元する。
通常のJSON/CSVインポートは蔵書の追加・更新用であり、本機能は内部IDを含むデータベース全体の置換用である。

## 設計

- バックアップ時はRoomの単一トランザクション内で `book_works`、`book_editions`、`owned_copies`、`wishlist_items`、`location_rooms`、`location_shelves`、`location_tiers`、`series`、`series_memberships`、`scan_sessions`、`scan_attempts` を読み出す。
- DBファイルはコピーしない。Roomのトランザクション分離により論理スナップショットを作るため、WALファイルの取りこぼしが発生しない。
- 復元前にZIP構造、形式版、DB版、件数、SHA-256、主キー重複、一意ISBN、外部キー参照、入力上限を検証する。
- 復元は全対象テーブルの削除・挿入を1回のRoomトランザクションで行い、親セッションを子試行より先に復元する。挿入または事後照合に失敗した場合、Roomが変更全体をロールバックする。
- 復元トランザクション内で現在状態の完全バックアップを先に作成し、`noBackupFilesDir/restore-backups` に原子的に保存する。保存直後に再読込してチェックサムと内容を検証し、復元の成功・失敗・キャンセルにかかわらず、現在分を含め最大3世代へ整理する。自己検証前に失敗したファイルは保持しない。
- 復元成功後はActivityタスクを再作成し、ViewModelと画面状態を復元後のDBから初期化する。

ファイル拡張子は `.ndcshelfbackup` で、ZIPには次の2エントリだけを格納する。

| エントリ | 内容 |
| --- | --- |
| `manifest.json` | 形式版、DB版、作成時刻、アプリ版、作品・版・所有コピー・購入候補・シリーズ・所属・スキャンセッション・試行の件数、ペイロード全体のSHA-256 |
| `database.json` | 蔵書、購入予定、置き場所、シリーズ、スキャン履歴のRoomエンティティ |

現在の形式版は10、DB版は9である。形式10ではスキャンセッションと試行履歴、形式9ではシリーズ所属の確定由来・確定者・候補生成時タイトル、形式8ではシリーズと所属、形式7ではISBNなし書誌と書誌情報の由来（`NDL` / `MANUAL`）を保持する。旧形式の書誌由来は`NDL`、形式8の所属は手動・ユーザー確定へ移行し、形式6より前は購入候補0件、形式8より前はシリーズ0件、形式10より前はスキャン履歴0件として扱う。現在より新しいDB版は、データを変更する前に拒否する。

## 安全性と制限

- 本機能は利用者が保存先を選ぶ手動バックアップであり、AndroidのOS管理バックアップとは独立している。OSクラウドからは全データを除外し、API 28以降の端末間転送だけRoom DBを対象にする。判断とOS別ルールは [BACKUP_THREAT_MODEL.md](BACKUP_THREAT_MODEL.md) を参照する。
- ユーザーが選んだ保存先のバックアップファイル自体は暗号化しない。タイトル、ISBN、読書状態、置き場所、欲しい・予約済み状態などの個人データを含むため、端末暗号化や保存先サービスの暗号化で保護する必要がある。
- 復元直前の自動バックアップはAndroidアプリのサンドボックス内にあり、Auto Backup対象外の `noBackupFilesDir` に保存する。
- 読み込み可能なアーカイブは25 MiB、展開後ペイロードは50 MiB、スキャン履歴を含む各テーブルは1万件、文字列合計は2,000万文字までに制限し、ZIP bombと過剰なメモリ消費を抑止する。
- 保存先の容量はStorage Access Framework側で事前取得できない場合がある。ユーザー向け書き出しは書き込み失敗時に既存DBへ影響せず終了する。
- 復元前には内部自動バックアップの2倍以上の空き容量を確認する。復元中の容量不足やプロセス停止はSQLiteトランザクションにより元のDBへ戻る。
- 自動バックアップの整理失敗は元の復元結果を上書きせず、個人データやファイル名を含めない警告を端末ログへ記録する。

## 受け入れ条件

- [x] Roomトランザクションの整合スナップショットによりWALを含む現在状態を取得できる。
- [x] 形式版、DB版、作成時刻、アプリ版、件数、SHA-256を保持する。
- [x] 復元前検証と現在DBの自動退避を行う。
- [x] 復元失敗を繰り返しても検証済み自動バックアップを最大3世代に制限する。
- [x] 全置換を原子的に実行し、失敗時にロールバックし、成功後にアプリ画面を再起動する。
- [x] 現形式の往復、旧形式移行、Room実DBの復元・ロールバックをテストする。
- [x] 個人データの内容と暗号化範囲をUIに表示する。
