# シリーズ新刊候補の実機確認

## 前提

- Android 13以降の端末と、通知権限確認のためアプリデータを消去できるdebug buildを使用する。
- 実在のシリーズ名を送信するため、テスト用シリーズ名以外の個人データを画面・ログ・Issueへ添付しない。
- 周期実行を待たずに確認する場合はAndroid StudioのWorkManager Inspectorを使用し、DBや本番コードの時刻を改変しない。

## 手順

1. シリーズ詳細を開き、定期確認が初期OFFで、送信するシリーズ名・最大週1回・NDL候補の限界が表示されることを確認する。
2. ONにして通知を拒否し、設定がOFFのまま、拒否メッセージが表示されることを確認する。
3. Android設定から通知を許可してONにし、WorkManager Inspectorで一意Work `series-release-watch`が1件、ネットワーク接続・battery-not-low・指数バックオフ制約付きであることを確認する。
4. 初回Workを実行し、候補は保存されるが通知されないことを確認する。
5. テストfixtureまたは新しいNDLレコードがあるシリーズで次回Workを実行し、シリーズごとに通知が1件だけ表示されることを確認する。同じ応答を再実行して通知が増えないことを確認する。
6. 通知を拒否して新候補を取得し、権限を戻した次回実行で未通知候補が通知されることを確認する。
7. 機内モードでWorkを実行し、保存済み候補が表示でき、Workがretryになることを確認する。
8. 端末時刻を過去へ変更して同じ応答を実行し、重複通知と最終成功日時の巻き戻りがないことを確認する。確認後に自動時刻へ戻す。
9. 端末を再起動し、一意Workが残っていることを確認する。完全バックアップを別の空状態へ復元してアプリを再起動し、有効な監視から一意Workが再作成されることも確認する。
10. OFFにして一意Workがキャンセルされることを確認する。複数シリーズのうち1件だけOFFの場合はWorkが残ることを確認する。

## 受け入れ条件

- [ ] 通知許可・拒否・後からの取り消しでクラッシュせず、拒否時に暗黙でONにならない
- [ ] 初回基準線、初見通知、同一候補の重複防止が成立する
- [ ] 外部障害、時計変更、再起動、backup復元後もローカルデータと一意Workが整合する
- [ ] ロック画面の公開通知にはシリーズ名・候補名が表示されない
- [ ] シリーズ画面のスマートフォン・大画面スクリーンショットをPRへ添付する
