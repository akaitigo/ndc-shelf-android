# スキャン実機検証手順

## 目的

暗所、小さいISBN、長時間の連続読取り、画面遷移で、CameraXのトーチ・ズーム・フォーカスとAnalyzerのライフサイクルが端末差を含めて安定することを確認する。

## 必須端末

同一メーカーの世代違いだけではなく、カメラ実装が異なる次の2系統以上で実施する。

| 系統 | 条件 | 記録項目 |
| --- | --- | --- |
| A | Google PixelまたはAOSPに近い端末、Android 15以降 | 機種、Android版、ビルド番号 |
| B | Samsung、Sony、Sharp等の別メーカー端末、サポート対象内のAndroid版 | 機種、Android版、ビルド番号 |

## 試験データと環境

- ISBN-13が異なる実物20冊以上を用意し、5周して100冊相当を読み取る。
- 通常照明（300 lux以上）と暗所（10 lux以下）を照度計または端末センサーで記録する。
- 小さいバーコードは短辺25 mm以下を含める。反射フィルム、曲面、低コントラストも各1冊以上含める。
- 機内モード試験以外は安定したネットワークを使用し、カメラ認識とNDL通信失敗を分けて記録する。

## 手順

1. 新規インストールでカメラ権限を拒否し、手入力が使えることと再要求説明を確認する。
2. 再度拒否して「今後表示しない」相当の状態にし、Android設定への導線と復帰後の権限再評価を確認する。
3. 通常照明で20冊を5周し、認識までの時間、誤認識、同一バーコードの多重通知を記録する。
4. 暗所でトーチを手動ONにして20冊を読み、画面離脱・アプリ背景化でトーチがOFFになることを確認する。
5. 小さいバーコードをピンチ拡大し、バーコード位置をタップしてフォーカス枠と認識改善を確認する。
6. フラッシュ、ズーム、AF/AEが非対応の端末またはカメラ構成では、操作が非表示または安全に無効化され、クラッシュしないことを確認する。
7. スキャンタブと他タブの往復、ホームへの前後遷移、画面回転を各20回行う。
8. 別のカメラアプリと競合させ、NDC Shelfが再試行可能な案内を表示することを確認する。
9. Android Studio Profilerまたは`adb shell dumpsys meminfo`で、試験前後にExecutor、Camera、ImageProxy由来の継続増加がないことを確認する。

## 合格基準

- 2系統それぞれで100冊相当を完走し、クラッシュ、ANR、ImageProxy滞留が0件。
- 正しいISBNの認識率が通常照明98%以上、暗所でトーチ使用時95%以上。
- 同一バーコード1回の提示に対する登録処理が1回で、誤ったISBN登録が0件。
- タップフォーカスとピンチズームの非対応時に例外や操作不能状態が発生しない。
- 画面離脱後にトーチが消灯し、カメラが他アプリから利用できる。
- 権限拒否、永久拒否、カメラ競合の各状態で、手入力または設定・再試行への行動が明示される。
