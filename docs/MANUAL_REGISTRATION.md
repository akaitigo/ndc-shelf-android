# 手動書誌登録とNDL照合

## 問題

NDL Searchに書誌がない資料や、通信できない状況でも蔵書へ登録できる必要がある。一方、ISBNの代わりに空文字や擬似値を保存すると一意制約、重複判定、将来のNDL照合を壊す。

## 設計

- ISBNなしの版は`book_editions.isbn13 = NULL`として保存し、Work・Edition・Copyには生成済みUUIDを永続IDとして割り当てる。
- `bibliographicSource`で`NDL`と`MANUAL`を区別する。通常の編集やISBNスキャンはこの値を自動変更せず、手動書誌を暗黙に上書きしない。
- 手動登録はタイトルだけ必須とし、著者未入力は表示・検索用に`著者不明`へ正規化する。ISBN、出版年、NDCは入力された場合だけ検証する。
- 後日照合はISBNでNDLを検索した後、現在値と候補値の差分を表示する。ユーザーが確定するまでRoomを変更しない。
- 同じISBNのEditionが存在する場合は、確認後に所有Copyを既存Editionへ移し、参照されなくなった手動Edition・Workを削除する。自動統合はしない。
- 照合プレビュー後に対象書誌またはISBNの対応先が変わった場合は競合として拒否し、最新状態での再確認を要求する。

## データ互換性

- Room DBはv7。v6以前のEditionは`bibliographicSource = NDL`へ移行する。
- JSON/CSVは書誌由来を保持する。JSON schema v3では`MANUAL`に限り`isbn13: null`を許可する。
- 完全バックアップはformat/payload v7。旧形式はISBN必須かつ`NDL`由来として復元する。
- SQLiteの一意インデックスは非NULL ISBNの重複を拒否し、複数のNULL ISBNを許可する。

## セキュリティ・運用

- 手動登録はネットワークを使用せず、入力上限とNUL文字、ISBNチェックデジット、出版年、NDC形式を検証する。
- NDL照合時に送信する値は入力されたISBNだけで、既存の蔵書情報は送信しない。
- 登録、統合、孤立行の削除はそれぞれ単一Roomトランザクションで行い、例外時は全変更をロールバックする。

## 受け入れ条件

- [x] NDL未検出または通信失敗の結果から手動登録を開ける。
- [x] タイトル必須、著者・ISBN・出版社・出版年・NDC・媒体種別任意で登録できる。
- [x] ISBNなしの複数書誌が安定した別IDでオフライン保存される。
- [x] 手動書誌が通常のISBN検索や編集で暗黙にNDL書誌へ置換されない。
- [x] 後日照合は差分と重複統合内容を表示し、明示確認後だけ反映する。
- [x] DB移行、重複、オフライン登録、競合、NDL照合、JSON/CSV/完全バックアップを自動テストする。

## ロールバック

DB v7へ移行済みの端末へDB v6のアプリを戻してはならない。機能を無効化する場合もDB列とnullable ISBNは維持し、修正版をv7以上で配布する。復旧が必要な場合は変更前にformat v7の完全バックアップを作成し、アプリの原子的復元経路を使用する。
